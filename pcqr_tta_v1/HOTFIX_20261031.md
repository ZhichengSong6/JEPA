# v0.1.1: SWM video-path compatibility fix

## Reported failure

Job 18840 produced FAILED.json with `TypeError: expected str, bytes or os.PathLike object, not NoneType` from `Path(video_path)` inside the installed SWM `evaluate_from_dataset`. No per-case result was successfully saved. This is an evaluator integration bug, not a result about TTA effectiveness.

The original runner passed `video_path=None` but omitted `save_video`. The inspected legacy SWM API defaults `save_video=True`; None does not disable recording.

## Change

`run_pusht.evaluate_case` now calls the existing evaluator with `save_video=False` and a non-null absolute path under the NEW run directory: `videos/<mode>_case<index>`.

The helper forwards dataset, episode, start, goal offset, evaluation budget and callables unchanged. It does not catch/retry evaluation errors. The manifest records the video-output policy. No changes to core adaptation, CEM, checkpoint selection, losses, update counts, initial-state checks, dependency versions or Slurm resources.

## Validation

38 local CPU tests passed, including four new tests covering the legacy Path conversion, forwarded evaluation arguments, distinct case/mode paths, disabled video writing, error propagation without retry, and the runner's use of the tested helper. Python compilation, CLI help and Bash syntax checks also passed.

These tests use an SWM API test double. The actual server checkpoint, SWM environment, CUDA and Slurm have NOT been executed for this hotfix. Passing unit tests does not establish closed-loop success.
